# Instructions for AI agents

- Follow [CONTRIBUTING.md](CONTRIBUTING.md) for branches, commits, pull requests, checks, and code style.
- Read [README.md](README.md) before changing the landing page, payments, or deployment.
- Read [admin/README.md](admin/README.md) and, when present, `admin/AGENTS.md` before changing the Payload admin panel or Telegram bot.
- Never put real credentials, private keys, Telegram sessions, customer details, order files, or database contents in code, tests, logs, issues, or pull requests.

## Work on a task

1. Inspect the relevant code and tests. Reuse existing helpers and configuration sources.
2. For a complex change, write a short plan before editing.
3. Add a failing test for a bug or new payment, order, or bot behavior. Implement the smallest fix, then refactor.
4. Review the diff for secret exposure, payment validation errors, duplicate messages, command injection, and accidental changes to customer data.
5. Run the relevant checks in [CONTRIBUTING.md](CONTRIBUTING.md#checks) before proposing a pull request. Report checks that could not run.

## Project constraints

- Edit source files in `src/`; `dist/` is generated by `scripts/build.mjs` and must not be committed.
- Keep one SCSS folder per BEM block in `src/scss/blocks/`. Preserve the cascade order in `src/scss/main.scss` and keep HTML classes consistent with SCSS and JavaScript selectors.
- Keep default prices and product names in `src/prices.json`. Verify browser totals and server-side payment calculations together when changing prices or discounts.
- Preserve webhook signature checks, server-side payment status verification, and protection against duplicate order processing or notifications.
- Keep credentials, orders, and SQLite databases outside the public web root. Use isolated temporary storage and fake customer data in tests and builds.
- For Payload schema changes, generate and review migrations, types, and the admin import map. Preserve existing data and verify database backup behavior before deployment.
- Preserve the separation between production and test sites, admin panels, bots, and order directories. The test site uses real payment APIs.
- Do not send real Telegram broadcasts, create real payments, or modify remote customer data without the owner's explicit instruction.
- Do not bypass checks or commit with `--no-verify`.

## Git

- Check the current branch and worktree before editing. Keep unrelated changes intact.
- Use one task per branch, based on current `main`. Name branches `<type>/<kebab-case>`; use a type from [CONTRIBUTING.md](CONTRIBUTING.md#branches).
- Keep dependent changes in separate branches and document the dependency.
- Do not push, open a pull request, merge, delete a remote branch, or change repository settings without the owner's explicit instruction. Pushes can trigger deployment, including replacement of the shared test environment.
