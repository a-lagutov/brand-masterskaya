# Ошибка HTML вместо JSON при проверке bulk-таблицы

Ветка `fix/bulk-preview-response` создана от актуального main после fetch.
Сначала требуется доказать источник HTML: CSV-парсер, API, авторизация или внешний HTTP-слой.

Установлено: локальный POST `/api/orders/bulk-preview` без авторизации возвращает HTTP 401
с валидным JSON. Запрос с этой машины к production получает HTML 503 с признаком сетевой
блокировки; это не доказывает ошибку приложения на сервере. SSH с этой машины не проходит
banner exchange. Поэтому источник production-ответа проверяется с GitHub runner без секретов,
без авторизации и без записи заказов, на синтетических CSV.

1. Получить HTTP status/content-type/JSON признак с независимого runner; не записывать реальные данные в тесты или логи.
2. Воспроизвести подтверждённый механизм тестом. Исправить только ответственный слой.
3. Проверить JSON-ошибки, HTML-ошибки, авторизацию и реальный read-only preview по HTTP.
4. Выполнить проверки CONTRIBUTING.md. Публикация исправления продолжает разрешённое владельцем исправление production-релиза через PR, без обхода main.
5. Удалить временный диагностический workflow из итогового PR после получения доказательства.

Дополнительно пользователь сообщил неверную привязку заказа к аккаунту. Правильный аккаунт
или разрешение просто отвязать ещё уточняется. Записи production без этой информации не менять.
Computer use запрещён; импорт и реальные рассылки для диагностики не запускать.
