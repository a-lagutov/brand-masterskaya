# План: запланированные и повторяющиеся рассылки

Ветка `feat/broadcast-schedules` зависит от локального коммита `533cffb` ветки `feat/admin-bulk-tools`: используются общий редактор и таблицы получателей. Перед созданием ветки выполнен `git fetch --prune origin`. Предыдущая задача сохранена отдельным коммитом с hooks; опубликованная история не меняется.

## Поведение

1. В существующей карточке рассылки выбрать отправку сейчас, однократно по дате либо ежедневно, еженедельно, ежемесячно. Начальная дата задаёт московское время и день повтора. Для повторов доступна дата окончания.
2. Предпросмотр и отдельная кнопка подтверждают запуск. Простое сохранение не включает расписание. После запуска настройки неизменны; остановка отменяет будущие запуски, текущая отправка завершается.
3. Каждое срабатывание создаёт отдельную рассылку с результатами доставки и ссылкой на расписание. Получатели и переменные вычисляются перед каждым запуском по сохранённым условиям; интерфейс объясняет это до подтверждения.
4. Повтор использует исходный календарный день; 31-е число сокращается до последнего дня короткого месяца без смещения следующих месяцев. Пропущенные интервалы не отправляются пачкой: один запуск после восстановления, далее ближайший будущий срок. Запуски одного расписания не пересекаются.
5. Существующий обработчик с RUN_BOT=1 проверяет расписания каждые 5 секунд. Уникальный ключ срабатывания, сохранённый дочерний запуск и восстановление продвижения расписания предотвращают повторное создание после перезапуска. Неопределённая доставка сохраняет существующую защиту от автоматического повтора.
6. Миграция добавляет поля, связи и индекс без изменения прежних рассылок; откат удаляет только новые поля. Проверить сохранность старых данных.

## Проверки и границы

Сначала RED календарных и интеграционных тестов, затем минимальный код и GREEN. Локальные контрольные коммиты RED/GREEN с Conventional Commits и Co-Authored-By; hooks обязательны. Проверить будущую дату, границы месяца/года, окончание, авторизацию, запрет подмены служебных полей, повторный tick, восстановление после создания запуска, остановку, отсутствие пересечений, оба отправителя и обратимость миграции. Генерировать types/import map/migration. Выполнить CONTRIBUTING checks на Node.js 22 и отдельной временной базе, дополнительно coverage новых функций. Проверить diff вручную на секреты, дубликаты сообщений и доступ.

Без новых сервисов, cron-выражений, внешних зависимостей и произвольных часовых поясов. Computer use запрещён. Не отправлять реальные сообщения, не менять удалённые данные. Push, PR и деплой — только по отдельной команде владельца.

создания запуска. Выполнена обратимая миграция с проверкой сохранности данных.
